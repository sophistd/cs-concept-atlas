## 读者与样例

计算机世界是一张可探索的计算机与软件工程地图，面向通过 AI、Coding Agent、Vibe Coding 开始做软件、却还不清楚部件分工的人。读者从正在遇到的问题出发，看懂相关方法、实现、资料之间的关系，再回到全域地图确定位置。本轮让第一次来的人知道网站的用途和起点，并完整走通一个有限样例。

反例：用户要按自家商品 SKU 分类，但权重的类别表不能表达这些 SKU。程序即使能输出标签，此方案也不满足目标；下一步先明确标签与数据，再比较适配/训练等候选。本轮只讲清不适用原因，不实施新训练方案。HTTP/2 与 SQLite 继续作为旧深链回归和模型反例，不扩成第二条完整内容路径；T01 存储选题仍待界定。

## 本轮唯一贯通样例

公共情境明确标为虚构。既有照片、目标标签和环境分别说明；方案能否尝试由必要条件决定，是否解决问题由实际结果检查决定。不会把用户浏览行为写成使用或学习状态，也不默认保存个人记录。

| 部分 | 必需对象/连接 | 本轮需讲清的答案 |
|---|---|---|
| 问题 | photo-classify → labels、input、inference、useful-result（全部需要） | 当前卡点在哪里，哪一步尚未检查 |
| 方案 | pretrained-inference / tv-resnet50-v2 | 目标标签适配、实现/环境/权重匹配；未知条件先确认 |
| 角色 | 预处理 → 推理 → 类别映射 → 结果评估；权重由实现加载 | 每个角色覆盖什么子问题，传入/传出什么，缺哪项仍不能完成 |
| 知识 | CNN #1453、ResNet、ResNet-50、V1.5、TorchVision 实现、V2 权重、ResNet 论文、作者发布物 | 家族/架构/变体/实现/参数/资料的区别；解释结构与实际执行的绑定用途不同 |
| 来源 | 逐主张/关系连接到材料版本与位置 | 该说法来自哪一节，有什么限定，哪些仍未检索/未实测 |
| 反查 | 知识/材料 → 同一绑定或关系 → 方案角色 → 子问题 | 反查仍带条件和角色，不只显示“CNN 用于分类” |
| 结果 | 单张调用检查 + 目标小样本判断 | 20 张中至少 18 张 top-1 匹配是虚构情境的示例判据，不是推荐阈值、文献标准或已测结果 |
