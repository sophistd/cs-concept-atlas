### #53 引擎 · 软件的构成单位
起源：有些活又重又通用 —— 渲染三维场景、执行 JavaScript、匹配正则、把数据可靠地落到盘上。这类活写一次要很久，写好了谁都能用。
机制：于是把它整块挖出来做成一个独立的核心，外面留一圈接口，别人在它上面盖东西。
判断：「引擎」是这一组里唯一没有硬分界线的词 —— 它不说明谁调用谁（那是库和框架的分界），也不说明能不能下载安装（那是包）。它只说明一件事：这里面有一坨你不想自己写的重活。所以同一个东西可以既是引擎又是库，V8 就是。判断这个词有没有被滥用，就看去掉「引擎」二字之后还剩下什么。

### #209 图 · 数据结构
起源：树能表达「从属」，表达不了「互相」。同学关系、网页链接、任务依赖、地铁线路里都有回路，用树一画就断。
机制：把「每个点只能有一个父」这条限制去掉，剩下的就是图 —— 一堆点，加上点之间的边，边可以有方向、有权重。
判断：树和图的分界只有一条：有没有回路。树是图的特例，不是另一个东西。代价也从这条线上长出来 —— 树上任何东西都能顺着一条路走到底，图上不行，所以图的算法几乎都要额外记一件事：我来过没有。忘了记，就是死循环。

### #275 动态规划 · 算法
起源：有些问题拆成子问题之后，子问题会重复出现。爬 n 级台阶要用到 n-1 和 n-2，而 n-1 又要用到 n-2 —— 同一个 n-2 被算了两遍。规模一大，重复次数是指数级的。
机制：把算过的记下来，下次直接取。就这一件事。
判断：动态规划不是一类算法，是一个避免重算的动作。它被讲得玄，是因为教科书从「状态转移方程」讲起 —— 那是结果，不是起点。起点永远是：先写出朴素的递归，发现有重复，才谈得上规划。分界线也在这儿 —— 能拆成子问题但子问题不重复，那是分治，不是动态规划。

### #413 依赖注入 · 设计模式
起源：一个类要用数据库连接，如果它自己 new 一个，就跟那个具体的数据库焊死了 —— 测试时换不成假的，换数据库要改它的代码。
机制：改成「我不自己造，谁用我谁塞给我」：构造函数收一个参数，或者由一个容器统一装配好再交给你。
判断：依赖注入常被当成一个框架功能，其实它只是把 new 挪了个地方。真正的分界在方向：原来是「我去找我要的东西」，现在是「我要什么由外面决定」—— 这就是控制反转，和「框架调用你，你不调用框架」是同一件事在两个尺度上的样子。

### #482 接口风格 · 架构风格
起源：两个服务要说话，得先约定一句话长什么样。三种流派对应三种世界观。
机制：REST 把一切看成资源，动词就 HTTP 那几个；RPC 把一切看成函数调用，只是函数在别的机器上；GraphQL 让调用方自己描述要哪些字段。
判断：分界不在技术新旧，在谁决定返回什么。REST 由服务端定死，于是有了「取一个列表要发三次请求」和「返回一大堆用不上的字段」这两个老毛病；RPC 由接口签名定死；GraphQL 把决定权交给调用方，代价是服务端再也无法预估一次查询有多贵。所以选哪个取决于调用方可不可控 —— 内部服务之间 RPC 最省事，对外开放给不认识的人 REST 最稳，前端要什么后端说不准时 GraphQL 最值。

### #509 函数式 · 编程范式
起源：程序难调试，很大一部分是因为同一段代码这次跑出来是这个、下次是那个 —— 因为它偷偷读了或者改了外面的东西。
机制：于是约束自己：函数只看参数、只返回值，不碰外面。同样的输入永远给同样的输出。数据不改，要变就造一份新的。
判断：函数式的价值不在优雅，在可替换 —— 一个纯函数随时可以被它的返回值替代，所以能缓存、能并行、能单独测试而不用搭环境。最常见的误解是把它当成「用 map/filter 不用 for」，那是语法。真正的分界是有没有副作用，跟用什么循环写法无关。

### #569 ML 家族 · 编程语言家族
起源：1970 年代 Robin Milner 做定理证明器，需要一门语言能保证类型不出错、又不必到处写类型标注。ML 就是那门元语言（Meta Language）—— 跟机器学习没有半点关系。
机制：两样东西是它的招牌：类型推断（你不写，编译器算出来）和模式匹配（按数据的形状分支，而且编译器逼你把情况写全）。
判断：这个家族的实际影响远大于它的使用率 —— 你今天在别的语言里觉得好用的东西，多半是从这儿抄的：Rust 的 Option / Result 和穷尽匹配、TypeScript 的类型推断和联合类型、Swift 的 enum with associated values。认得这条血缘，那些特性就不用当孤立语法一条条记。

### #694 指针与引用 · 语言的构成部件
起源：一个大对象要传给函数，整份复制太贵；两个地方要看同一份数据，一复制就不是同一份了。
机制：那就不装东西本身，装它在内存里的地址。传地址是固定的小代价，而且大家指的确实是同一份。
判断：指针难，难的不是概念，是它把「这个名字」和「名字指的东西」拆成了两样，而日常语言里这两样是一回事。于是「改这个变量」有了歧义：是改地址（让它指向别处），还是改地址指的那块（改内容）？几乎所有指针 bug 都掉在这条缝里。引用是把这条缝焊上的产物 —— 不许换指向，只能改内容，用灵活性换掉了这一整类错误。

### #732 强类型与弱类型 · 类型系统
起源：两门语言都在跑之前不检查类型，但一个遇到 1 + "2" 会报错，另一个会算出 "12"。前者是 Python，后者是 JavaScript —— 它们都是动态类型。可见「动态」没说完。
机制：静态和动态说的是什么时候检查（编译时还是运行时）；强和弱说的是发现类型对不上时，是报错还是偷偷帮你转。
判断：这是两根正交的轴，不是一根轴的两端。四个象限都住着人：Java 静态强、Python 动态强、C 静态弱（指针能强转成任意类型）、JavaScript 动态弱。把它们当成一根轴是这个域里最常见的错误，后果是让人以为「加了 TypeScript 就不会有类型问题了」—— 而 TS 管的只是编译期那一半，运行时那一半它一点也管不着。

### #819 系统调用 · 操作系统
起源：程序要读文件、开网络、申请内存，这些都得碰硬件。但如果谁都能直接碰，一个程序崩了会拖垮整台机器。
机制：CPU 分两种模式。普通程序跑在权限低的那种，碰不到硬件，要办事只能喊一声，切进内核模式让操作系统代劳，办完再切回来。
判断：系统调用是程序和操作系统之间唯一的门 —— 你用的每一个库函数，只要真的碰了外部世界，往下扒到底都是一条系统调用。所以它也是性能的分水岭：一次调用要切两次模式，代价比普通函数调用高一两个数量级。缓冲、批量写、mmap、io_uring，这些优化其实是同一个名字：少过几次门。

### #882 传输层 · 网络与协议
起源：网络层只负责把包送到那台机器，不保证送到、不保证顺序、不保证不重复。可上层的程序要的是「我发的这段字，对面原样收到」。
机制：TCP 在不可靠的通道上补出可靠 —— 编号、确认、丢了重发、按序交付，顺带还控制发多快免得把网堵死。UDP 不补，原样透传。
判断：分界不在谁更好，在谁来承担乱序和丢包。TCP 替你担了，代价是它会为了等一个丢掉的包，卡住后面所有已经到了的数据（队头阻塞）—— 这对传文件是对的，对直播和游戏是灾难，因为迟到的那一帧就算补回来也没用了。所以视频会议、游戏、QUIC 全都选 UDP，然后只补自己需要的那部分。

### #1000 隔离级别 · 数据库与存储
起源：事务保证「要么全成要么全不成」，但没说在你还没做完的时候，别人能看见多少。而完全隔离（所有事务排队一个个跑）太慢。
机制：于是分档卖：读未提交、读已提交、可重复读、可串行化。越往上越像「整个库只有你一个人在用」，也越慢。
判断：这一组的名字都是按它防住了哪种异常起的，所以要倒过来记 —— 脏读是看见了别人还没提交的，不可重复读是同一行读两次不一样，幻读是同一个条件查两次行数变了。分界线是你的业务能不能容忍这一次异常。还有一个坑：默认值不是安全值，MySQL 默认可重复读、PostgreSQL 默认读已提交，同一份代码搬过去行为就变了。

### #1049 竞态条件 · 并发与并行
起源：两个线程同时给一个计数器加一，结果可能只加了一次。因为「加一」不是一个动作，是读出来、加、写回去三个动作，中间可以被插进来。
机制：只要多个执行流访问同一份数据、至少有一个在写、而且没有说清先后，结果就取决于谁先跑到 —— 而这不由你决定。
判断：竞态最恶的地方不是它会出错，是它大部分时候不出错。时序取决于机器、负载、编译器优化，所以它能在你机器上跑一万次都对，上线第二天挂一次，而且复现不了。所以对付它靠的不是测试（测不出来），是从设计上让它不可能发生：要么不共享，要么共享的东西不可变，要么共享时强制排队。

### #1121 即时编译 · 从源码到运行
起源：编译器先全翻完，跑得快但改一次要等一次；解释器边读边跑，启动快但每一行都要重新理解一遍。两边各有各的难受。
机制：先解释着跑，同时统计哪段代码跑得最多；跑热了的那几段再编译成机器码，之后直接执行机器码。
判断：JIT 能比提前编译还快（不只是接近），是因为它掌握了静态编译器拿不到的东西 —— 运行时的真实数据。这个循环实际只走了三次、这个多态调用点九成九都是同一个类型，据此可以做提前编译不敢做的激进优化，赌错了再退回去。代价是启动慢、吃内存、性能有预热期。「编译器⟷解释器」那条分界线，到这儿是合流的。

### #1147 前端框架 · 前端
起源：界面要跟着数据变。手写就是「数据改了，我记得去把这几个 DOM 节点也改掉」—— 项目一大，「记得改哪些」就成了 bug 的主要来源。
机制：于是反过来 —— 你只写「数据是这样时界面该长这样」，框架去算出差异，替你改 DOM。
判断：这一层的核心不是组件、也不是虚拟 DOM，是把「怎么改」从你手里拿走。所以它必然要调用你（你写的是被它调用的描述），这也是「库⟷框架」那条线在前端的落点。选型上真正的差别不在语法，在它怎么知道数据变了：React 靠你显式告诉它，Vue 和 Solid 靠劫持数据的读写自动追踪。这一条决定了心智负担落在哪一边。

### #1226 会话与身份 · 后端
起源：HTTP 每一次请求都是独立的，服务器天生不记得你。可几乎所有应用都要记住「你还是刚才那个你」。
机制：登录成功后发一个凭证，之后每次请求带着它。凭证要么是一把只有服务器认得的钥匙（Session，状态存在服务端），要么是一张服务器签过名的纸条（JWT，状态就写在纸条上）。
判断：分界在状态存哪，而这一条直接决定了能不能立刻把人踢下线。Session 在服务端删一下就失效；JWT 已经发出去的纸条在过期前一直有效，想撤销就得再维护一张黑名单 —— 而那等于又把状态搬回了服务端。所以「JWT 无状态所以更好」这句话，只在你不需要即时撤销的时候成立。

### #1286 容器化 · 交付与基础设施
起源：「在我机器上是好的」—— 因为程序依赖的不只是它自己，还有一堆库、环境变量、目录结构、系统版本。
机制：把程序连同它需要的整个用户态环境打包成一个镜像，运行时靠内核的命名空间和 cgroups 隔出一块地方来跑。
判断：容器和虚拟机最容易混，分界只有一条 —— 共不共用内核。虚拟机自己带一整个操作系统，所以能在 Linux 上跑 Windows，代价是重、启动以秒计；容器共用宿主机内核，所以轻、启动以毫秒计，代价是跑不了别的内核，隔离也弱一档（内核一破就全破）。「容器是轻量级虚拟机」这个说法方便，但会误导 —— 它们隔离的根本不是同一层东西。

### #1372 覆盖率 · 测试
起源：写了测试，但不知道漏没漏。于是记录跑测试的时候，哪些行被执行到了。
机制：行覆盖、分支覆盖、路径覆盖，粒度依次变细 —— 分支覆盖会追问「这个 if 的两条路都走过吗」。
判断：覆盖率只能证伪，不能证实 —— 没覆盖到的地方肯定没测，覆盖到了却完全不代表测对了，一个不带任何断言的测试照样能把覆盖率跑满。所以它的正确用法是去看没覆盖的那部分，而不是追一个百分比。一旦把它定成 KPI，人就会去写那种「调用一遍但什么都不检查」的测试 —— 这时候指标涨了，测试反而更差了。

### #1407 密码哈希 · 安全
起源：密码不能明文存，库一泄就全完。可普通哈希（MD5、SHA-256）也不行 —— 它们是为快而设计的，显卡一秒能算几十亿次，常见密码一撞就出来。
机制：那就反过来，故意设计得慢，而且慢的程度可调（迭代次数、内存占用）。再给每个密码配一撮随机的盐，让攻击者没法算好一张表打所有人。
判断：这是整个领域里少有的、「慢」是功能而不是缺陷的地方。判据也因此反直觉 —— 一个密码哈希算法好不好，看的是它能不能抵抗专用硬件。所以现代的 bcrypt、Argon2 不只耗 CPU 还故意耗内存，因为显卡和矿机能堆算力，堆不了那么多内存。看到有人用 SHA-256 存密码，那是用错了工具，不是参数没调好。

### #1511 向量检索 · 人工智能与机器学习
起源：关键词检索匹配的是字面。用户搜「怎么让狗别叫」，文档里写的是「犬类吠叫行为矫正」，一个字都不重合，于是搜不到。
机制：把文本或图片先用模型压成一串数字（向量），意思相近的向量在空间里离得近。检索就变成了「找离我最近的那几个点」。
判断：它的代价被讲得太少 —— 它把「精确」换成了「相似」。你没法保证某个必须命中的词一定被命中，也没法解释为什么这一条排在前面。而且几百万个点做精确最近邻太慢，实际都用近似索引（HNSW、IVF），那又再牺牲一点召回换速度。所以真实系统里它极少单独用，多半和关键词检索混合打分 —— 它补的是字面匹配的短板，不是替代品。

### #1533 字符编码 · 数据的表示与格式
起源：机器只存字节，可人要写的字有几十万个。早期一个字节 128 个位置只够拉丁字母（ASCII），于是各国各自把高位那 128 个位置占了，中文还得用两个字节。同一串字节，用不同的表去查，出来的字完全不同 —— 这就是乱码。
机制：Unicode 先给世界上每个字发一个唯一编号（码点），UTF-8 再规定这个编号怎么写成字节：ASCII 那部分保持一个字节不变，其余用二到四个字节。
判断：关键是把两件事分开 —— 「这个字的编号是多少」（Unicode）和「编号怎么写成字节」（UTF-8 / 16 / 32）。混作一谈就会问出「Unicode 和 UTF-8 哪个好」这种问题。还有一条：一个字符不等于一个字节，也不等于一个「长度」—— emoji 和带声调的字母常常由好几个码点组合而成，所以同一个字符串的长度，在不同语言里能算出不同的答案。

### #1592 Git 的对象 · 版本控制与协作
起源：Git 看着有几十条命令，记不住是因为大家都从命令学起。但它底下的模型极小。
机制：只有四种东西，全部按内容算哈希存起来 —— blob 是一份文件内容，tree 是一个目录（文件名指向 blob 或 tree），commit 是一个 tree 的快照加上父 commit 和作者信息，tag 是给某个对象起的名字。分支不是一份拷贝，只是一个指向某个 commit 的可移动指针，实际就是一个文件里的一行。
判断：懂了这个模型，命令就不用背了 —— 每条命令都只是在挪指针或者造对象。commit 造一个新对象并把分支指针往前挪；branch 新建一个指针；reset 把指针挪到别处（内容对象还在，所以能找回来）；merge 造一个有两个父的 commit。「Git 难」多半难在这一层没建立起来，于是每条命令都成了要单独记的咒语。

### #1659 存储层级 · 计算机体系结构
起源：又快又大又便宜的存储不存在 —— 快的（寄存器、SRAM）贵且小，便宜又大的（磁盘）慢好几个数量级。
机制：于是摞成一层层：寄存器 → L1/L2/L3 缓存 → 内存 → SSD → 磁盘。每往下一层，容量涨、单价降、延迟涨，相邻两层常常差十到一百倍。
判断：这一摞之所以能成立，全靠一个经验事实 —— 局部性：刚用过的东西很可能马上再用，用了某个位置很可能马上用它旁边的。程序要是不符合局部性，这一摞就全白搭。很多反直觉的性能现象都从这儿来：为什么按行遍历二维数组比按列快好几倍，为什么链表在小数据量上常常打不过数组 —— 复杂度一样，但一个顺着缓存行走，一个到处跳。

### #1697 时间复杂度 · 理论计算机科学
起源：同一个算法在不同机器上跑出来的秒数不一样，没法比较。要比的是算法本身，就得把机器快慢、常数开销这些都去掉。
机制：只看输入规模 n 变大时，操作次数怎么涨。大 O 记的是增长的量级，常数和低阶项一律扔掉。
判断：扔掉常数是它的力量，也是它最常被误用的地方 —— O(n) 不一定比 O(n log n) 快，n 小的时候尤其如此，所以实际的排序库都是「大了用快排，小了切成插入排序」。它回答的是「数据涨十倍会怎样」，不回答「现在快不快」。另外大 O 说的是上界，通常还得说清是最坏、平均还是摊还 —— 哈希表那个 O(1) 是平均，最坏是 O(n)。
