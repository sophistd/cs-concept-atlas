# data/ · 地图分类、解释与来源
> L2 | 父级: ../CLAUDE.md

- `concepts.json`: 原有节点分类、父子与跨域关系；数组下标不得静默移动。旧 g/m 留作沿革，浏览器正文由 entries 叠加。
- `bundles.json`: 已采用的组合与人工名称，成员同时保存下标及名称供构建检查。
- `entries/`: 按 24 个领域维护的逐节点解释与来源，构建时核对原节点身份，不向分类库回写。
- `objects.json`: B01 的 11 个知识身份及正文引用；CNN、PyTorch 复用旧 raw，其余对象使用独立命名空间。
- `problems.json`: 照片分类及四个必要子问题；分解边表达共同完成条件，不能推导已解决。
- `solutions.json`: 一个预训练推理方案及完整变体、四个职责、三个条件、四条必要连接引用和分层检查判据；绑定与覆盖不得隐含新增必要条件。
- `mappings.json`: 角色绑定、问题覆盖、协作连接和来源支持的对象关系；加载协作引用同一对象关系核对方向，正反索引由编译器派生。
- `scenarios.json`: 三个显式虚构情境的条件与绑定使用记录；调用/结果检查固定四个实际部件版本及条件快照，不接收私人状态。

原分类维护曾更正 SQLite 与 C 的关系标签为“用什么语言实现 / 用于实现”，依据 entries 中的 SQLite 官方介绍。B01 不改 concepts/bundles 的身份、位置或关系；其他原关系仍需审校。

五份 B01 定义共享 formatVersion=1 与样例版本，由 scripts/atlas.mjs 的 readAtlas 在 entries 编译后读取。正文只在 entries 维护；来源逐项保留材料版本、定位和分发依据。情境判定的未知、调用结果、问题结果彼此独立，不因阅读或选择绑定升级为实测。该数据接口没有下载、模型执行或个人保存能力。

原分类保留不代表判断已全部审定。资料可访问性、字段齐全、解释准确性是不同检查；来源日期只在确实核对过页面时填写。
